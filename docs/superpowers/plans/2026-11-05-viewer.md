# VisualShower Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build a local Next.js / Three.js viewer with orbit and free flight.

**Architecture:** A client React interface owns import state and viewer settings. An imperative Three.js engine owns the canvas, loaders, controls and GPU cleanup. Pure scene and file helpers are tested independently.

**Tech Stack:** Next.js, React, TypeScript, Three.js, lucide-react, Node test runner via tsx.

**Spec:** docs/superpowers/specs/2026-11-05-viewer-design.md

## Global Constraints

- Use Next.js and Three.js; keep model handling local to the browser.
- Russian UI, two inspection modes, responsive viewport.
- Do not replace the visible model on failed imports.

## Review Focus

- Empty or unsupported imports return a clear error.
- Companion resources with encoded paths or duplicate basenames resolve correctly.
- Tiny, large, offset or empty models do not break framing.
- Switching modes and losing focus clear flight input.
- Repeated imports and Strict Mode cleanup do not leak animation loops or GPU resources.
